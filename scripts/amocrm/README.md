# Настройка отдела поддержки в amoCRM

Скрипт создаёт базовую структуру отдела поддержки через официальный API amoCRM v4. Повторный запуск безопасен: существующие воронки, этапы, группы и поля не дублируются, ничего не удаляется.

## Что будет создано

- воронка `Поддержка сайтов` с этапами обработки заявок;
- воронка `Сайты на сопровождении` для действующих договоров;
- группа полей сделок `Поддержка сайтов`;
- группа полей компаний `Сопровождение сайтов`;
- поля для домена, приоритета, типа задачи, SLA, сроков, часов и результата;
- поля для тарифа, договора, оплат VPS и домена, бэкапов и контактов клиента;
- поля сделок видны только в воронке `Поддержка сайтов`;
- обязательность домена, типа задачи и приоритета на этапах `В очереди` и `В работе` при первоначальном создании полей.

Скрипт не создаёт тестовых сделок и не меняет существующие данные.

Ограничение видимости работает через `hidden_statuses` и требует подключённой
платной функции amoCRM `Супер-поля`. Без неё API amoCRM отклонит настройку
видимости. Поля компаний остаются глобальными: карточка компании не относится к
конкретной воронке.

## Подготовка доступа

1. Войдите в amoCRM под администратором.
2. Создайте приватную интеграцию в разделе интеграций amoCRM.
3. Получите долгосрочный токен доступа.
4. Не сохраняйте токен в репозитории, `.env` или истории команд.

Документация amoCRM:

- [авторизация интеграций](https://www.amocrm.ru/developers/content/oauth/step-by-step);
- [воронки и этапы](https://www.amocrm.ru/developers/content/crm_platform/leads_pipelines);
- [поля и группы полей](https://www.amocrm.ru/developers/content/crm_platform/custom-fields).

## Запуск

Нужен Node.js 18 или новее.

```bash
export AMOCRM_BASE_URL="https://example.amocrm.ru"
read -s AMOCRM_ACCESS_TOKEN
export AMOCRM_ACCESS_TOKEN
```

Сначала запустите проверку. Это режим по умолчанию, он только читает настройки аккаунта:

```bash
node scripts/amocrm/setup-support.mjs
```

После проверки примените изменения:

```bash
node scripts/amocrm/setup-support.mjs --apply
```

Не запускайте несколько копий `--apply` одновременно. Если связь оборвётся во
время записи, скрипт остановится и попросит запустить его ещё раз: новый запуск
сначала перечитает состояние amoCRM и продолжит только с отсутствующих объектов.

Вместо полного адреса можно передать поддомен:

```bash
export AMOCRM_SUBDOMAIN="example"
export AMOCRM_TLD="ru"
```

Для создания воронок и полей токен должен принадлежать администратору аккаунта.

## Что нужно завершить вручную

Публичный API amoCRM не предоставляет полного управления настройками Digital Pipeline, типами задач, сотрудниками и каналами обращений. После выполнения скрипта настройте в интерфейсе:

1. Подключение почты, форм и рабочих мессенджеров.
2. Права сотрудников и доступ к двум новым воронкам.
3. Типы задач: ответ клиенту, выполнение, проверка, напоминание.
4. Автоматическую задачу на ответ при поступлении новой заявки.
5. Назначение исполнителя и срока при переходе в `В очереди`.
6. Напоминание клиенту на этапе `Ожидаем клиента`.
7. Задачу на проверку при переходе в `Проверка`.
8. Сообщение клиенту при переходе в `Ожидаем подтверждения`.
9. Циклические задачи по проверке бэкапов, оплат и ежемесячных отчётов.

Настройка автоматических действий Digital Pipeline доступна на тарифе amoCRM `Расширенный` и выше.

## Проверка скрипта

```bash
node --test scripts/amocrm/setup-support.test.mjs
```

Если в аккаунте уже существует одноимённое поле с другим типом, скрипт остановится и ничего нового в этой группе не создаст. Сначала переименуйте конфликтующее поле либо скорректируйте конфигурацию скрипта.
